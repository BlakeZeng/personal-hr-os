# Fictional practice rules

These rules govern only this exercise. Ari authorises preparation, not HR approval or execution. Chen owns both lists and resolves missing information and conflicts. Bo decides any employment change; Eli receives a complete draft but no receipt is implied. Dev controls case identity and index reconciliation.

Read all event and reference rows. The primary key is PersonRef: trim leading/trailing whitespace only, case-sensitive; preserve originals. No fallback or fuzzy matching. Reference keys must be unique: if a key repeats, hold every affected event row; do not select a record. An event with no reference match is unmatched and held. Event row identifiers must be unique; hold duplicates and ask Chen. Do not assume people absent from Events.csv are cases to prepare.

Required on each event: EventID, PersonRef, EventType, EffectiveDate and ProposedValue. Joining also requires Documents; movement and offboarding require CurrentValue to agree exactly with Reference.csv CurrentValue. Reference Name must be present. For joining, ProposedValue is the proposed team and Documents is evidence availability text only, not document verification. For movement, ProposedValue is the proposed team. For offboarding, ProposedValue is the proposed status. EventType must be joining, movement or offboarding. Dates are ISO calendar dates and must agree with reference ExpectedDate; missing or invalid dates and disagreement are held. Blank or whitespace-only fields are missing. Compare field values exactly after trimming outer whitespace; do not infer a correction or use case folding. If multiple issues apply, list all visible issues. Hold affected rows for Chen; include each row and evidence in the handover. A clear row is ready for HR review only, never approved or implemented.

A complete draft identifies all input rows and results, evidence, each open exception and owner/action, source owners, recipient, and unconfirmed HR approval, update and receipt. Read back outputs and verify the record/index relationship. Receiving acceptance requires explicit dated evidence from Eli, not merely a prepared file; none is supplied in BASE. A draft may be prepared with held exceptions if they are clearly described; leave unresolved work open.
