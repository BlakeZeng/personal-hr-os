# Record codebook

Draft neutral record method. The owner confirms local numbering, timezone, storage and action authority through the [organisation profile](../Context/Organisation%20Profile%20Template.md). Do not infer those values from an old environment.

## Case identity and storage

An independently managed case, cycle or project uses one stable identity and one canonical current record. A simple conversational answer needs no new case unless its owning procedure requires one. Public starter work stores remain empty; live records and testing outputs belong in controlled private or isolated test copies.

Find the existing event/cycle in [Case Index](Case%20Index.md) before creating a record. Reuse the identity and latest verified state, retaining earlier decisions. For new identities, the V2 structural pattern is PILLAR-TYPE-YYYYMMDD-NNN; the owner confirms the namespace, timezone, registering stream and allocator before use. Keep T for Task and P for Project where that local convention is adopted. Do not fabricate identity/date values or preallocate future cases. An interrupted registration resumes the same identity rather than creating a duplicate.

If the Case Index is missing, repeats an identity, or points that identity to a different case/event, hold registration or resumption for the named case owner. Do not silently repair the register, allocate another identity or overwrite a record. If a required canonical record or governing source is unavailable, report it and its owner; withhold the affected completion claim. A prepared handover without the named receiver's applicable acceptance remains unaccepted.

## Record structure

Use [Work Record](Templates/Work%20Record.md) and the [Tag bank](Tag%20bank.md).

- P1 Brief: requested outcome, scope, authority, current state, accountable handler and next action.
- P2 Workflow: numbered checkpoints, actual sources, responsible people, precise stage, verification and unresolved conditions.
- P3 Analysis, decisions and learning: conditional case reasoning using Finding, Evidence, Applies to, Action and Verification. Detailed reusable procedures stay in their owning skills.

The fixed P2 columns are Checkpoint | Source | PIC | Status | Detail. Status contains only one circle: 🟢, 🟡 or 🔴. Put stage wording and explanation in Detail. A completed draft is distinct from approved execution; submitted, approved, sent, received and fulfilled outcomes remain separate.

## Resumption and verification

Read the latest verified state, relevant sources and next owner before resuming. Recheck dependencies invalidated by changed sources or new evidence. Save material progress/decisions in the same record; no running diary or second status register is required.

Verify saved outputs and applicable receiving acceptance before closing the agreed scope. A missing approval, unresolved source or unfinished assigned checkpoint stays open with its owner/action. A narrow preparation result may close separately only when its endpoint is clear. Preserve dated material decisions rather than overwriting them.

## Controlled references and learning

Use [Controlled Reference](Templates/Controlled%20Reference.md) for a maintained rule when needed, retaining its actual source authority and applicability. Metadata alone does not approve a rule. P3 Recorded means captured; Implemented needs a saved authorised change and checks; Demonstrated effective needs evidence from later use. No automatic skill change, schedule, publication or career transfer follows a case finding.
